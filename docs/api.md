# API contract

Base URL: `http://127.0.0.1:8000`. Send JSON with `Content-Type: application/json`. Full request/response schemas are available at `/openapi.json` and `/docs` while the API runs.

## Routes

| Method | Path | Behavior | Success |
| --- | --- | --- | --- |
| GET | `/api/oshi` | List all oshi, including inactive, with nested keywords; priority descending, then ID ascending. | 200, array |
| POST | `/api/oshi` | Create an oshi and its optional keywords. | 201, oshi |
| PATCH | `/api/oshi/{id}` | Edit supplied oshi fields; a supplied keyword array replaces the set. | 200, oshi |
| DELETE | `/api/oshi/{id}` | Delete the oshi/keywords/links, retain updates and refresh their scores. | 204, empty body |
| GET | `/api/updates` | List updates with combined filters and pagination. | 200, array |
| GET | `/api/updates/{id}` | Get one update, including its `oshi_ids`. | 200, update |
| POST | `/api/updates` | Create an update, validate associations, calculate score. | 201, update |
| PATCH | `/api/updates/{id}` | Merge supplied fields with the stored record, validate, recalculate score. | 200, update |
| PATCH | `/api/updates/{id}/status` | Change status only. | 200, update |
| GET | `/api/stats` | Global counts of oshi and updates, grouped by category and status. | 200, stats |
| GET | `/api/discover` | Ranked local catalog search by canonical name and aliases. | 200, array |
| POST | `/api/discover/{entity_id}/track` | Track a catalog entity or return its existing tracked Oshi. | 201 new / 200 existing, oshi |

Unknown resource IDs return 404. Invalid JSON fields, enum values, ranges, URLs, dates, duplicate associations, or unknown linked `oshi_ids` return 422. Errors use FastAPI's `{"detail": ...}` envelope; details may be a message, validation list, or the unknown-association object. Unknown JSON request fields and unknown update-list query fields are rejected. Mutations are atomic.

## Oshi and keywords

Discovery is separate from tracking: see [Discover](#discover) below. Manual creation through `/api/oshi` remains independent of the catalog.

Oshi creation requires `name` (1–200 trimmed characters) and `type`. Optional `priority` is an integer 0–100 (default 50), `active` defaults to `true`, and `keywords` defaults to `[]`. Each keyword requires a nonblank `value` (up to 200 characters); `weight` is an integer 0–100 (default 1). At most 100 keywords per oshi are accepted.

Oshi responses contain `id`, `name`, `type`, `priority`, `active`, `created_at`, and `keywords`. Each keyword response includes `id`, `oshi_id`, `value`, and `weight`.

```sh
curl -sS http://127.0.0.1:8000/api/oshi \
  -H 'Content-Type: application/json' \
  -d '{"name":"原神","type":"GAME","priority":80,"keywords":[{"value":"ナヒーダ","weight":25}]}'

curl -sS -X PATCH http://127.0.0.1:8000/api/oshi/1 \
  -H 'Content-Type: application/json' \
  -d '{"keywords":[{"value":"リヴァイ","weight":25}],"active":true}'
```

Use the ID returned by the create/list endpoint in subsequent requests; IDs in examples are placeholders. Keyword matching normalizes Unicode and case. `keywords: []` clears keywords; omission preserves them. Required oshi values cannot be explicitly set to `null`.

## Updates

Create requires `title` (1–500 characters), `category`, `source` (1–200 characters), and HTTP(S) `source_url` (up to 2048 characters). URLs are stored, never fetched.

| Field | Type / default |
| --- | --- |
| `summary` | String, max 20,000 characters; default `""`. |
| `published_at` | Timestamp with timezone offset, or `null`. |
| `start_date`, `end_date` | `YYYY-MM-DD` calendar dates, or `null`. End must not precede start when both exist. |
| `deadline` | Timestamp with timezone offset, or `null`. |
| `location` | Nonblank string up to 300 characters, or `null`. |
| `status` | Status enum; default `NEW`. |
| `oshi_ids` | Up to 100 distinct existing positive integer IDs; default `[]`. |

`id`, `created_at`, and `relevance_score` are generated by the server and cannot be supplied in a request. Responses contain all model fields plus `oshi_ids` sorted ascending. Timestamps are normalized to UTC and serialized with `Z`. Naive timestamps are rejected. Categories, types, and statuses use the uppercase values in [the spec](spec.md).

PATCH omits unchanged values. Explicit `null` clears only the nullable timestamp/date/location fields. `oshi_ids: []` removes all associations. `summary: ""` clears the summary. Empty `{}` is a valid no-op patch. Existing fields participate in date validation even if not supplied in the patch.

```sh
curl -sS http://127.0.0.1:8000/api/updates \
  -H 'Content-Type: application/json' \
  -d '{"title":"[DEMO] 原神 ナヒーダのグッズ","summary":"架空の開発用サンプル","category":"MERCH","source":"Demo fixture","source_url":"https://example.invalid/demo/merch","deadline":"2026-10-01T23:59:00+09:00","oshi_ids":[1]}'

curl -sS -X PATCH http://127.0.0.1:8000/api/updates/1/status \
  -H 'Content-Type: application/json' \
  -d '{"status":"SAVED"}'

curl -sS -X PATCH http://127.0.0.1:8000/api/updates/1 \
  -H 'Content-Type: application/json' \
  -d '{"deadline":null}'
```

## Filters and pagination

`GET /api/updates` accepts:

| Query | Meaning |
| --- | --- |
| `oshi` | One positive integer oshi ID; matches an explicit association, including inactive oshi. Unknown ID returns an empty list. |
| `category` | One update-category enum. |
| `status` | One update-status enum. |
| `min_score` | Inclusive integer minimum, 0–100. |
| `limit` | Page size, 1–200; default 50. |
| `offset` | Nonnegative integer offset; default 0. |

All supplied filters are combined with AND. Results sort by relevance score descending, then creation timestamp descending, then ID descending for stable ties. Updates linked to multiple oshi appear once. With no status filter, all statuses, including `IGNORED`, are returned. Pagination returns an array; there is no filtered-total envelope in v0.1.

```sh
curl -sS 'http://127.0.0.1:8000/api/updates?oshi=1&category=MERCH&status=SAVED&min_score=65&limit=20&offset=0'
```

## Stats

`GET /api/stats` returns global, unfiltered counts. Every enum bucket appears even when its count is zero. Updates count once regardless of the number of linked oshi. `active_oshi` counts active oshi only; `total_oshi` includes inactive ones.

For an empty database:

```json
{
  "total_oshi": 0,
  "active_oshi": 0,
  "total_updates": 0,
  "by_category": {"NEWS": 0, "EVENT": 0, "MERCH": 0, "COLLAB": 0, "MOVIE": 0, "RELEASE": 0, "OTHER": 0},
  "by_status": {"NEW": 0, "SAVED": 0, "INTERESTED": 0, "GOING": 0, "BOUGHT": 0, "IGNORED": 0}
}
```

## Discover

`GET /api/discover?q=Higedan` returns `Official髭男dism`. Candidates contain `id`, `name`, `type`, nullable `description`, `aliases` (strings), `provider`, and `is_tracked`. Provider is `local` for the bundled collection. Search makes no external requests.

Queries allow up to 200 characters. Missing, blank, or whitespace-only queries return `[]`; unknown queries also return `[]`. `limit` defaults to 20 and accepts 1–50. Search applies Unicode NFKC, case folding, and whitespace removal to canonical names, aliases, and queries. Literal `%` and `_` are not wildcards. Ranking is canonical exact, alias exact, canonical prefix, alias prefix, canonical substring, then alias substring; ties sort by normalized canonical name and ID. No typo correction, transliteration, or semantic matching is implied beyond supplied aliases.

`is_tracked` is true when an explicit catalog link exists, or an existing Oshi of the same type has a normalized name matching the canonical name or one of its aliases. Paused rows still count as tracked; this operation never silently reactivates them. If multiple legacy/manual rows match, the lowest ID is reused. Names with different types remain distinct. Existing linked identity takes precedence over name matching and survives later renaming.

`POST /api/discover/{entity_id}/track` needs no body. It creates an ordinary Oshi with the canonical name/type, priority 50, active true, and deduplicated canonical/alias keywords at weight 1. New tracking returns 201; duplicate requests return the same Oshi with 200 and do not change personal fields. Unknown catalog IDs return 404. Concurrent discovery tracking is serialized by SQLite before looking up the existing link, and the link is unique per entity/Oshi.

Deletion remains `DELETE /api/oshi/{id}`. It removes the personal following and optional catalog link, retains update history, and leaves catalog entities/aliases intact. Searching and tracking the entity again is supported; old update associations are not automatically restored. Manual creation never requires or inserts a catalog entity.
